# Routing and query

Read this reference for Dropzone routing, cross-Vault decisions, new-Vault recommendations, or read-only knowledge queries.

## Routing

- Choose the primary Vault by the source's future use and main query, not by every topic or keyword it contains.
- Each Vault extracts only knowledge within its scope.
- Prefer an existing Vault. Recommend a new one only when actual staged files form a growing, independently useful collection with a distinct long-term query purpose or access boundary.
- A recommendation names its supporting files and proposes a name, scope, exclusions, routing question, and Vault-level sensitivity.
- Routing and recommendation do not authorize creation. Run a generator only after an explicit new-Vault command.
- A Dropzone file must enter a Vault's Inbox before it can become a formal source.

If one source genuinely serves independent purposes in multiple Vaults, the user may place a copy in each relevant Inbox. Each Vault processes only its own scope and remains self-contained.

Keep every Vault understandable on its own. Add a cross-Vault pointer only when the user explicitly wants one and it materially helps navigation.

## Query

1. Start with `3-Wiki/index.md` and relevant Wiki pages.
2. Read detailed summaries for provenance and Inbox only when original evidence must be checked.
3. Never treat AI notes or outputs as independent evidence.
4. A query is read-only unless the user explicitly requests persistence or a deliverable.

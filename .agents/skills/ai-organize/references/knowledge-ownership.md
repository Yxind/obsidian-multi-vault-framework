# Knowledge ownership

Read this reference when a rough analysis, detailed summary, or ingestion task must decide where knowledge belongs.

## Page responsibilities

- **Topic:** a problem, context, constraints, method combination, and result.
- **Concept:** one mechanism or method that remains understandable and reusable outside one project.
- **Tool:** an executable checklist, configuration, template, or acceptance standard.
- **People:** a person and their verifiable views.
- Keep one-off examples, project history, and immature ideas in their Topic or analysis note.

## Candidate order

Decide in this order:

1. **Link only** when an existing page already owns the knowledge.
2. **Update and link** when the source adds evidence, a boundary, correction, counterexample, or operational step.
3. **Create** only when no page owns a distinct responsibility with credible long-term reuse.
4. **Keep local** when the material is contextual or immature.

Use a link only when it helps understanding, verification, execution, or reuse. Label the relation nearby, such as `应用`, `依赖`, `支持`, `扩展`, `修正`, or `矛盾`. Prefer one meaningful link to repeated keyword links.
